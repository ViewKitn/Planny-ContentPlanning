# Planny — Planning Decisions

เอกสารระหว่างการสัมภาษณ์ ข้อเสนอที่ยังไม่ได้ตอบไม่ถือเป็นข้อกำหนดที่ยืนยันแล้ว

## Confirmed constraints

- Web Application สำหรับจัดการ Content Lifecycle
- Tech Stack หลัก: Vue 3 + Spring Boot + PostgreSQL
- UI แบบ Modern SaaS ที่ใช้งานง่าย
- ทำ Core Features ให้สมบูรณ์ก่อนเพิ่ม AI หรือการโพสต์อัตโนมัติ

## Round 1 — Confirmed

- ผู้ใช้หลักรุ่นแรกคือครีเอเตอร์ที่ทำงานคนเดียว
- เส้นทางหลักเริ่มจากคิดไอเดีย เตรียมคอนเทนต์ และวางแผนเผยแพร่
- ผู้ใช้บันทึกการเผยแพร่จริงด้วยมือได้
- แยกวันและเวลาตามแผนออกจากวันและเวลาที่เผยแพร่จริง
- แนบลิงก์โพสต์ที่เผยแพร่แล้วได้

## Round 2 — Historical decisions (see Round 3 for revisions)

- Content เป็นงานหลักและมี Publication แยกต่อช่องทาง
- แต่ละ Publication มีข้อความ กำหนดเผยแพร่ และข้อมูลเผยแพร่จริงของตนเอง
- เขียน brief, สคริปต์ และ caption ในระบบได้
- แนบลิงก์ไฟล์จากภายนอกได้ การอัปโหลดและจัดเก็บภาพ/วิดีโอเลื่อนไปภายหลัง
- หนึ่งบัญชีมีหลาย Brand ได้ แต่ละ Brand มีช่องทาง คอนเทนต์ และปฏิทินของตนเอง
- รุ่นแรกไม่มีสมาชิกทีมหรือการแชร์สิทธิ์

## Open design branches

- ไม่มีประเด็นค้างจากการสัมภาษณ์ ผู้ใช้ยืนยันสเปกและเกณฑ์ตรวจรับแล้วใน Q27

## Interview status

ผู้ใช้ยืนยันว่าเข้าใจตรงกันและอนุญาตให้ลงมือขั้นตอนถัดไปแล้ว เริ่มพัฒนาตาม planny-spec.md

## Round 3 — Confirmed and revised

- ผู้ใช้ระบุว่าปกติโพสต์พร้อมกันทุกแพลตฟอร์ม และต้องการรวมเป็นงานเดียวแทนการแยก Publication ต่อช่องทาง รายละเอียดสถานะรวมและกรณีเผยแพร่บางแพลตฟอร์มยังรอคำตอบ
- รุ่นแรกเน้นครีเอเตอร์หนึ่งคนที่ดูแลหนึ่งเพจ ไม่แยก Brand แทนขอบเขตหลาย Brand ที่ตกลงใน Round 2
- ไม่ได้ยืนยันการจัดการหลายบัญชี/เพจต่อแพลตฟอร์มตามข้อเสนอ Q7
- Content เก็บชื่อ ไอเดีย/brief สคริปต์ และลิงก์อ้างอิง; caption และลิงก์ไฟล์ที่ใช้จริงแยกต่อแพลตฟอร์ม การแก้เนื้อหาหลักไม่เขียนทับ caption ที่เตรียมไว้แล้ว (Q8)
- งานตามแผนที่เลยเวลายังคง Planned และแสดงว่าเลยกำหนด ผู้ใช้เลื่อนวันหรือบันทึกการเผยแพร่จริงเองได้ ปฏิทินมีเดือน/สัปดาห์ เขตเวลาเริ่มต้น Asia/Bangkok (Q9); การตั้งเขตเวลาจะต้องปรับจากระดับ Brand ที่ถูกถอดออก
- รุ่นแรกเป็นเครื่องมือส่วนตัว ไม่มีบัญชีผู้ใช้ สมัคร/เข้าสู่ระบบด้วยอีเมลและรหัสผ่านพร้อมกู้รหัสผ่านเลื่อนไป MVP ภายหลัง (Q10)
- ใช้ Tags พร้อมค้นหาชื่อ/เนื้อหา และกรองสถานะ แพลตฟอร์ม Tag และช่วงวันเผยแพร่ Campaign ทำภายหลัง (Q11); ไม่มีขอบเขต Tag แยก Brand ในรุ่นแรก
- รองรับ Archive และถังขยะที่กู้คืนได้ การลบงานต้องพาข้อมูลการเผยแพร่ที่เกี่ยวข้องไปด้วย และการปิดใช้ปลายทางต้องเก็บประวัติเดิม (Q12); รายละเอียดปลายทางรอข้อสรุปโมเดลใหม่

## Round 4 — Confirmed

- Content หนึ่งชิ้นมีสถานะเดียว: Idea → Draft → Ready → Planned → Published
- ใช้กำหนดเผยแพร่และเวลาเผยแพร่จริงร่วมกันทุกแพลตฟอร์ม
- caption ลิงก์ไฟล์ และลิงก์โพสต์แยกตามแพลตฟอร์ม ไม่มี Publication ที่มีสถานะหรือกำหนดแยกต่อแพลตฟอร์ม
- Published หมายถึงเผยแพร่ครบทุกแพลตฟอร์มที่เลือกแล้ว หากยังไม่ครบให้คง Planned
- รุ่นแรกใช้งานผ่าน localhost และเก็บข้อมูลถาวรใน PostgreSQL การเข้าผ่านอินเทอร์เน็ตจากอุปกรณ์อื่นจะอยู่ในช่วงเพิ่มระบบบัญชีภายหลัง
- brief/สคริปต์รองรับหัวข้อ ตัวหนา และรายการ; caption เป็นข้อความธรรมดาที่คัดลอกไปโพสต์ได้
- บันทึกอัตโนมัติพร้อมแสดงกำลังบันทึก บันทึกแล้ว และบันทึกไม่สำเร็จ

## Round 5 — Confirmed

- เลือก Facebook, Instagram, TikTok, YouTube ได้ทันที และเพิ่มชื่อแพลตฟอร์มอื่นเองได้ ไม่ต้องตั้งค่าบัญชีหรือเพจ
- สร้าง Content ด้วยชื่ออย่างเดียวได้ ผู้ใช้กำหนด Draft/Ready เอง
- Planned ต้องมีแพลตฟอร์มอย่างน้อยหนึ่งแห่งและวันเวลาเผยแพร่
- Published ต้องมีแพลตฟอร์มอย่างน้อยหนึ่งแห่งและเวลาเผยแพร่จริง บันทึกงานที่เผยแพร่แล้วได้โดยไม่ต้องผ่านทุกสถานะ; caption และลิงก์ไม่บังคับ
- ปฏิทินแสดง Planned ตามกำหนด และ Published ตามเวลาเผยแพร่จริง โดยรายละเอียดงานเก็บกำหนดเดิมไว้
- เขตเวลาตั้งระดับเครื่องมือและเปลี่ยนได้ เริ่มต้น Asia/Bangkok
- ถังขยะไม่มีการลบอัตโนมัติ กู้คืนข้อมูลเนื้อหา สถานะ แพลตฟอร์ม และลิงก์เดิมครบ การลบถาวรต้องยืนยัน Archive แยกจากถังขยะ
- Export/Import ไฟล์สำรอง ครอบคลุม Content, Tags, ข้อมูลรายแพลตฟอร์ม, Archive และ Trash ตรวจไฟล์และยืนยันก่อน Import แทนที่ข้อมูลเดิม
- หน้าหลัก: บอร์ดสถานะ/รายการ ปฏิทินเดือน/สัปดาห์ รายละเอียดคอนเทนต์ คลัง/ถังขยะ และการตั้งค่า
- เปิดมาที่บอร์ดงาน เน้นเดสก์ท็อป Dashboard สถิติแยกทำภายหลัง

## Round 6 — Confirmed

- แก้ข้อมูล Content ที่ Published ได้ พร้อมแจ้งว่าการแก้ใน Planny ไม่เปลี่ยนโพสต์จริง
- เผยแพร่ซ้ำด้วย Duplicate เป็น Draft ใหม่ ไม่มีวันเผยแพร่หรือลิงก์โพสต์เดิม
- ย้อนสถานะ Published เพื่อแก้การบันทึกผิดต้องยืนยันก่อนล้างเวลาเผยแพร่จริงและลิงก์โพสต์
- ลากงาน Planned บนปฏิทินเพื่อเปลี่ยนวันโดยคงเวลาเดิม งาน Published เปลี่ยนวันที่ผ่านรายละเอียด
- ยกเลิกกำหนดแล้วกลับ Ready และล้างกำหนดเผยแพร่
- เก็บร่างที่บันทึกไม่สำเร็จในเบราว์เซอร์ มีการลองบันทึกใหม่และเตือนก่อนออกจากหน้าที่มีข้อมูลค้าง เปิดกลับมาให้เลือกกู้ร่างโดยไม่เขียนทับฐานข้อมูลทันที
- ปิดใช้แพลตฟอร์มเพื่อไม่ให้เลือกในงานใหม่ โดยเก็บข้อมูลเดิมไว้
- ลบ Tag ต้องยืนยัน เอาป้ายออกจากงานที่เกี่ยวข้อง แต่ไม่ลบ Content
- UI ภาษาไทย ชื่อสถานะตามที่ตกลงพร้อมคำอธิบายไทย Light Mode ตัวหนังสืออ่านง่าย พื้นที่เขียนกว้าง และสีสถานะมีข้อความกำกับ
- หลายภาษาและ Dark Mode ทำภายหลัง
