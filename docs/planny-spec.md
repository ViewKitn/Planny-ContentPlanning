# Planny — Core Features Specification

สถานะ: ผู้ใช้ยืนยันความเข้าใจร่วมกันและอนุญาตให้ลงมือพัฒนาแล้ว สเปกนี้รวบรวมข้อสรุป Q1–Q26 และเกณฑ์ตรวจรับที่ยืนยันแล้ว

## เป้าหมายและขอบเขต

เครื่องมือส่วนตัวสำหรับครีเอเตอร์หนึ่งคนที่ดูแลหนึ่งเพจ จัดการงานตั้งแต่คิดไอเดีย เตรียมเนื้อหา วางแผน ไปจนถึงบันทึกการเผยแพร่จริง ใช้ Vue 3 + Spring Boot + PostgreSQL รันบนเครื่องตนเองผ่าน localhost และเก็บข้อมูลถาวรใน PostgreSQL

รุ่นแรกมีพื้นที่งานเดียว ไม่มี Brand บัญชีผู้ใช้ สมาชิกทีม หรือการแชร์สิทธิ์ การสมัคร/เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน การกู้รหัสผ่าน และการเข้าผ่านอินเทอร์เน็ตจากอุปกรณ์อื่นอยู่ใน MVP ภายหลัง

## โมเดลคอนเทนต์

- Content เป็นงานหลักหนึ่งชิ้น มีชื่อ ไอเดีย/brief สคริปต์ ลิงก์อ้างอิง และ Tags
- Content เลือกหลายแพลตฟอร์มได้ ใช้สถานะ กำหนดเผยแพร่ และเวลาเผยแพร่จริงร่วมกัน ไม่มี Publication แยกต่อแพลตฟอร์ม
- แต่ละแพลตฟอร์มมี caption ลิงก์ไฟล์ที่ใช้จริง และลิงก์โพสต์ของตนเอง
- การแก้เนื้อหาส่วนกลางไม่เขียนทับ caption ที่เตรียมไว้
- brief/สคริปต์รองรับหัวข้อ ตัวหนา และรายการ; caption เป็นข้อความธรรมดาที่คัดลอกไปโพสต์ได้
- ใช้ลิงก์ไฟล์ภายนอก ยังไม่มีระบบอัปโหลด/จัดเก็บภาพหรือวิดีโอ
- เลือก Facebook, Instagram, TikTok, YouTube ได้ทันที และเพิ่มชื่อแพลตฟอร์มอื่นเองได้ ไม่ต้องตั้งค่าบัญชีหรือเพจ
- ปิดใช้แพลตฟอร์มเพื่อไม่ให้เลือกในงานใหม่ได้ โดยเก็บข้อมูลของงานเดิม
- แพลตฟอร์มหลักแสดงโลโก้ในบอร์ด รายการ ตัวเลือก และส่วน caption; แพลตฟอร์มอื่นใช้ไอคอนทั่วไป
- หน้าโปรไฟล์เพจบันทึกลิงก์หน้าเพจต่อแพลตฟอร์ม และเปิดลิงก์ที่บันทึกไว้ในแท็บใหม่ได้ ลิงก์นี้แยกจากลิงก์โพสต์ของแต่ละ Content

## วงจรงาน

| สถานะ | ความหมาย/เงื่อนไข |
| --- | --- |
| Idea | เริ่มงานได้ด้วยชื่ออย่างเดียว |
| Draft | กำลังเตรียมเนื้อหา ผู้ใช้กำหนดสถานะเอง |
| Ready | พร้อมเผยแพร่ ผู้ใช้กำหนดสถานะเอง |
| Planned | มีแพลตฟอร์มอย่างน้อยหนึ่งแห่งและกำหนดเผยแพร่ |
| Published | ผู้ใช้บันทึกว่าเผยแพร่ครบแพลตฟอร์มที่เลือก มีแพลตฟอร์มอย่างน้อยหนึ่งแห่งและเวลาเผยแพร่จริง |

ไม่บังคับให้ผ่านทุกสถานะตามลำดับ บันทึกงานที่เผยแพร่แล้วโดยตรงได้ caption และลิงก์โพสต์ไม่บังคับ ส่วนลิงก์โพสต์เพิ่มภายหลังได้

หากเผยแพร่ยังไม่ครบแพลตฟอร์มให้คง Planned หากกำหนดผ่านไปแล้วยัง Planned ให้แสดงว่าเลยกำหนด ไม่เปลี่ยนเป็น Published อัตโนมัติ การบันทึกเผยแพร่จริงเป็นการบันทึกด้วยมือ และแยกจากกำหนดเดิม

### การแก้ไขและทำซ้ำ

- แก้ข้อมูลที่ Published ได้ พร้อมแจ้งว่าไม่เปลี่ยนโพสต์จริงบนแพลตฟอร์ม
- Duplicate สำหรับการเผยแพร่ซ้ำสร้าง Content ใหม่เป็น Draft โดยไม่ติดวันเผยแพร่หรือลิงก์โพสต์เดิม
- ย้อนสถานะ Published เพื่อแก้การบันทึกผิดต้องยืนยันก่อนล้างเวลาเผยแพร่จริงและลิงก์โพสต์; สถานะปลายทางต้องผ่านเงื่อนไขของสถานะนั้น
- ยกเลิกกำหนดของ Planned แล้วกลับ Ready พร้อมล้างกำหนดเผยแพร่

## ปฏิทิน

- มุมมองเดือนและสัปดาห์
- Planned แสดงตามกำหนดเผยแพร่; Published แสดงตามเวลาเผยแพร่จริง โดยรายละเอียดเก็บกำหนดเดิมไว้
- ลาก Planned เพื่อเปลี่ยนวันได้ โดยคงเวลาเดิม
- Published เปลี่ยนวันที่ผ่านหน้ารายละเอียด
- ตั้งเขตเวลาระดับเครื่องมือ เริ่มต้น Asia/Bangkok

## ค้นหาและจัดหมวดหมู่

- ใช้ Tags; Campaign อยู่ภายหลัง
- ค้นหาชื่อ/เนื้อหา และกรองตามสถานะ แพลตฟอร์ม Tag และช่วงวันเผยแพร่
- ลบ Tag ต้องยืนยัน เอาป้ายออกจากงานที่เกี่ยวข้องโดยไม่ลบ Content

## คลัง ถังขยะ และการสำรอง

- Archive เก็บงานแยกจากรายการงานที่กำลังทำ และไม่ใช่การลบ
- ลบ Content ลงถังขยะพร้อมข้อมูลรายแพลตฟอร์มที่เกี่ยวข้อง
- ถังขยะไม่ลบอัตโนมัติ กู้คืนแล้วได้เนื้อหา สถานะ แพลตฟอร์ม และลิงก์เดิมครบ
- ลบถาวรต้องยืนยัน
- Export/Import ไฟล์สำรอง ครอบคลุม Content, Tags, ข้อมูลรายแพลตฟอร์ม, Archive และ Trash
- ตรวจไฟล์และให้ยืนยันก่อน Import แทนที่ข้อมูลเดิม

## การบันทึกและการกู้ร่าง

- บันทึกอัตโนมัติ แสดงกำลังบันทึก บันทึกแล้ว และบันทึกไม่สำเร็จ
- เมื่อบันทึกไม่สำเร็จเก็บร่างในเบราว์เซอร์ ให้ลองบันทึกใหม่ และเตือนก่อนออกจากหน้าที่มีข้อมูลค้าง
- เปิดกลับมาให้เลือกกู้ร่าง โดยไม่เขียนทับข้อมูลใน PostgreSQL ทันที

## หน้าจอและทิศทาง UI

- เปิดมาที่บอร์ดสถานะ มีมุมมองรายการด้วย
- ปฏิทินเดือน/สัปดาห์
- หน้ารายละเอียดคอนเทนต์และพื้นที่เขียนเนื้อหา
- คลังและถังขยะ
- การตั้งค่า รวมเขตเวลา แพลตฟอร์ม และสำรอง/นำเข้าข้อมูล

Modern SaaS เน้นเดสก์ท็อป UI ภาษาไทย ใช้ชื่อสถานะ Idea/Draft/Ready/Planned/Published พร้อมคำอธิบายไทย เริ่มด้วย Light Mode ตัวหนังสืออ่านง่าย พื้นที่เขียนกว้าง สีสถานะมีข้อความกำกับ

Dashboard สถิติแยก หลายภาษา Dark Mode ระบบ AI และการโพสต์อัตโนมัติอยู่ภายหลัง

## เกณฑ์ตรวจรับที่เสนอ

1. สร้างไอเดียด้วยชื่อ เตรียม brief/สคริปต์ และ caption หลายแพลตฟอร์มได้ โดยแก้เนื้อหาหลักแล้ว caption เดิมไม่เปลี่ยน
2. วางแผนโดยใช้วันเวลาร่วมกันได้; ข้อมูลไม่ครบตามเงื่อนไข Planned/Published ต้องไม่ถูกบันทึกเป็นสถานะนั้น
3. ปฏิทินเดือน/สัปดาห์แสดงงานตามกฎ ลาก Planned แล้ววันเปลี่ยนและเวลาเดิมยังอยู่ ยกเลิกกำหนดแล้วกลับ Ready
4. งานเลยกำหนดยังคง Planned; บันทึก Published ด้วยมือและลิงก์รายแพลตฟอร์มได้ กำหนดเดิมกับเวลาเผยแพร่จริงแยกกัน
5. Duplicate ได้ Draft ใหม่โดยไม่ติดวันเผยแพร่หรือลิงก์โพสต์เก่า และย้อน Published แล้วล้างข้อมูลตามกฎหลังยืนยัน
6. ค้นหา/กรองตามเงื่อนไขได้ ลบ Tag แล้วงานยังอยู่ ปิดแพลตฟอร์มแล้วประวัติงานเดิมยังอยู่
7. Archive, ลบลงถังขยะ, กู้คืน และลบถาวรทำงานตามกฎ โดยการกู้คืนรักษาข้อมูลที่เกี่ยวข้องครบ
8. ปิดและเปิดระบบใหม่แล้วข้อมูลที่บันทึกยังอยู่ใน PostgreSQL
9. เมื่อ backend ไม่พร้อม ร่างไม่หาย มีสถานะผิดพลาด/ลองใหม่ และกู้ร่างได้โดยไม่เขียนทับฐานข้อมูลทันที
10. Export แล้ว Import กลับได้ข้อมูลตามขอบเขตครบ ไฟล์ไม่ถูกต้องไม่แทนที่ข้อมูล และต้องยืนยันก่อนแทนที่
